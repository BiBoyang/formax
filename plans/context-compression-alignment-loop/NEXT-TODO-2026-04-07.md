> `microcompact`、`collapse`、`prune` 现在已经存在，但它们还没有形成真正独立的 query-time 中间层策略栈。

Claude Code 当前明显更强的地方，不只是某个单独策略，而是 query 前有一组更明确分工的中间层：

1. tool-result budget replacement
2. snip
3. microcompact
4. collapse projection
5. auto/full compact

1. 先把 middle-layer stack 的阶段语义、执行顺序与 terminal fallback 讲清楚

3. 再把这些 stage facts 做成真正可消费的 control-plane diagnostics
4. `CCA-143` 已完成；下一阶段不再是“先回答 snip 边界”，而是基于 post-143 状态重新排优先级
