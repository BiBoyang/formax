## Todo

### `CCA-150` working-set / keep strategy v4

已完成：
- working-set anchor 现在不再只有固定的 1-turn rewind 语义。
- `Read` anchor 继续保持 1 个 extra user turn 的回卷窗口。
- `filesystem_cluster` anchor 现在有独立的 2-turn backtrack window。
- `/context` diagnostics 现在会显式暴露：
  - `anchorKind`
  - `anchorToolNames`
  - `anchorBacktrackTurns`
  - `anchorMaxBacktrackTurns`

当前定位：
- 这是 working-set v4 的第一刀，不是最终 task-minimal selector。
- 它解决的是“filesystem exploration 明明还在当前任务里，但只因多了一轮用户迭代就被视为 stale”的问题。

### `CCA-151` session-memory restore consumption v4

目标：
- 让 session-memory 不只停留在 file-backed restore 的 one-turn reminder 注入
- 继续扩大 restore 后可直接消费的 session-memory surface

已完成：
1. app-server `thread/resume` 现在不再只复用 `mode` / `planPath` 语义；它也会复用 `nextTurnInjectedBlocks`
2. app-server 会把 session-memory reminder 作为服务端缓存的 next-turn-only injected blocks，在下一次成功的 `turn/start` / turn-dispatch 上消费一次
3. `/context` local diagnostics 现在会把这批 pending restore injected blocks 暴露到 next-turn fixed groups

当前定位：
- 这是一条 restore-consumption widening，而不是新的 persisted authority model
- 它继续保持 canonical restore-artifacts 单一路径；没有重新引入第二套 sidecar 读取或 reminder 组装逻辑

### `CCA-152` middle-layer canonical-owner convergence

目标：
- 继续减少 `contextCompressionService.ts` 中 stack 外的直接 helper 路径
- 让 middle-layer stack 更接近 surrounding flow 的唯一 owner

已完成：
1. `prepareHistoryForTurn()` 仍保留 auto-threshold 前的轻量 microcompact 预处理，但 post-compact 的 persisted baseline materialization 已改由 canonical stack owner 负责
2. `runReactiveCompact()` 不再手工串联 `applyCompactedHistory`；reactive retry 现在直接复用 canonical stack 来同时产出 persisted `history`、request-time `requestHistory` 与 prepared trailing user
3. `runManualCompact()` 与 `finalizeHistoryAfterTurn()` 不再把 terminal `prune` 写回 future-turn baseline；它们现在改为取 canonical stack 的 persisted-history candidate

当前定位：
- 这是一轮 owner convergence，而不是新的 reducer 扩张
- 现在 stack 外仍允许保留 pre-auto 的轻量 microcompact 预处理，但 surrounding flow 的 persisted baseline materialization 已不再各自手搓 `microcompact + prune`

### `CCA-153` compact protocol remote / restore alignment

目标：
- 继续补 compact boundary / preserved segment / remote restore 的生态差距

已完成：
1. app-server `thread/resume` 现在会直接返回 canonical `latestCompactBoundary`
2. Web runtime 的 `resumeThreadInputs()` 现在会在 restore path 直接消费这份 compact protocol fact，并更新 thread-scoped compact boundary cache
3. `thread/resume` / `thread/read` / `thread/messages` 现在共享同一套 compact boundary 来源，没有引入新的 persisted authority model

结果：
- compact protocol 的 remote / restore alignment 已完成最小闭环：
  - restore surface 不再需要额外调用 `thread/read` 才能感知最近一次 compact boundary
  - app-server / Web parity 继续建立在 canonical compact protocol 上，而不是局部特判

### `CCA-160` task-minimal working-set selector v5

已完成：
1. working-set anchor 不再只围绕 filesystem cluster；当前已新增 `task_execution_cluster`
2. selector 现在会显式把 recent task planning/todo state 与 recent code-reading / code-editing cluster 的组合相关性纳入 keep strategy
3. `/context` diagnostics 当前已暴露：
   - `taskStateKinds`
   - `selectionReasons`
   - `anchorKind=task_execution_cluster`

结果：
- current keep strategy 已从“filesystem cluster-aware”推进到“task-minimal working-set”第一版。
- 这轮仍然不改 persisted authority model；变化只在 compact-side tail selection 与 diagnostics 解释面。

### `CCA-161` session-memory restore utility v5

已完成：
1. canonical restore-artifacts 路径现在不再只返回 `nextTurnInjectedBlocks`；它还会返回结构化 `pendingSessionMemoryRestore`
2. `thread/resume` 当前会直接暴露这份 next-turn-only restore utility 摘要
3. `thread/replay` 当前也会在 pending 窗口内暴露同一份摘要，直到下一次成功的 `turn/start` / turn-dispatch 消费掉 reminder blocks
4. Web strict parser 已同步支持这份结构化 restore utility surface

结果：
- session-memory 不再只以 reminder 文本形式存在于 restore flow 中；当前至少已有 restore / replay 两个 surface 可直接消费结构化 task-state utility
- 仍然没有引入第二套 reminder 组装路径
- sidecar 仍然是 best-effort，不是新的 persisted authority

### `CCA-162` compact protocol replay / inspection parity

目标：
- 让 compact protocol 的消费不只停在 read/messages/resume surface，而能更深进入 replay / inspection

预期范围：
1. 至少一个 replay / inspection surface 开始直接消费 compact boundary / preserved segment facts
2. 保持 compact protocol 仍然以 canonical replay 为唯一来源
3. 不引入 restore-only / replay-only 第二套 compact summary

验收：
1. 至少一个 replay / inspection 入口开始直接读取更完整的 compact protocol fact
2. app-server / Web parity 继续建立在 canonical compact protocol 上
