# 方法论：如何抓包 & 如何写结论

这一章写给“第一次做逆向/对齐”的同学：怎么从命令行现象，变成可落地的工程结论。

## 1) 建议的素材类型

- **命令行输出（最好手动复制一份）**：最能表达“用户看到的现象”
- **抓包/请求记录**：最能表达“模型实际收到了什么提示、调用了哪些工具”
- **录屏/录制（如 asciinema cast）**：最能表达“交互时序”（按键、滚动、闪烁、展开等）

## 2) 建议的推导流程

1) 先写“现象”（不要急着解释）
2) 再列“证据”（✅：能从抓包/复现直接看到）
3) 再写“推断”（🧩：如果没有证据就不要写成事实）
4) 最后落到“工程行为”：Formax 要不要对齐？对齐到什么程度？哪些做成 TODO？

## 3) 如何避免误导

- 看到一个行为 ≠ 证明它是“硬规则”
- 一个版本的行为 ≠ 永远都这样（尽量标注版本/日期）
- 很多“提示词文字”只是为了引导模型，并不代表产品内部一定这么实现

## 4) 安全与隐私

- 永远不要把 API key / token / cookie 写进 repo
- 贴抓包片段时优先“删掉无关字段，只留关键片段”
- 文件路径可以用 `~` 或 `<HOME>` 表示，避免暴露个人信息
