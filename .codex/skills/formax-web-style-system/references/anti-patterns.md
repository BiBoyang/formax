# Anti-Patterns

Reject outputs with these traits:

1. Flat single-color pages with no atmospheric layering.
2. Generic default SaaS clone look (especially Inter + purple bias by habit).
3. Dark-mode-first direction when not requested.
4. Excessive micro-motion or decorative animation noise.
5. Weak state hierarchy where action priority is unclear.
6. Hard-coded ad-hoc style values without token architecture.
7. Screenshot mimicry at pixel level instead of mood translation.
8. Ambiguous focus states that reduce keyboard accessibility clarity.
9. Over-shadowed card stacks that make utility settings screens feel heavy.
10. Saturated rainbow accents across content surfaces that break calm operational tone.
11. Thick borders and dense outlines that replace spacing-based hierarchy.
12. Marketing-style oversized CTAs in productivity/settings contexts.
13. Opaque solid sidebars when glass/translucent material is required.
14. Flat page backgrounds that hide sidebar transparency behavior.
15. Default bordered input fields when soft-filled borderless inputs are required.
16. Missing top context navigation (back link or breadcrumbs) in settings/detail canvases.
17. Primary form actions buried inline at the end of long content flow.

## Correction Heuristics

- If visuals feel generic, improve surface hierarchy and typographic intent first.
- If visuals feel loud, reduce saturation and motion before changing structure.
- If visuals feel unclear, increase state contrast and simplify component tiers.
- If styling is inconsistent, re-anchor everything to tokens and semantic states.
- If settings screens feel cluttered, flatten card depth and strengthen row/divider rhythm.
- If design feels unlike the target references, verify glass sidebar + wallpaper mesh + soft-filled inputs first.
