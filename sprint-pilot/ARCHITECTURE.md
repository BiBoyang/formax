# ARCHITECTURE

最后更新：2026-02-27

本文件是 `sprint-pilot/` 的架构地图模板，参考 agent-first 工程实践，强调“可导航、可校验、可演进”。

## 1. 目标

1. 为人类与 agent 提供统一的系统地图（不是实现细节堆叠）。
2. 明确边界与依赖方向，减少跨层漂移。
3. 让文档与代码共同成为可执行事实来源。

## 2. 分层模型（建议）

1. `Types`：领域类型、schema、契约声明
2. `Config`：配置解析、特性开关、环境约束
3. `Repo`：外部 I/O 适配（DB、FS、RPC）
4. `Service`：领域规则与用例编排
5. `Runtime`：会话/任务/状态机执行
6. `UI`：页面、组件、交互呈现

依赖方向：只允许从上层依赖下层的前序层（单向），禁止反向依赖。

## 3. 语义与渲染分离

1. 业务语义状态机与 UI 展示必须解耦。
2. UI 只能消费 view model，不直接承载语义纠偏逻辑。
3. realtime 与 replay（或恢复）必须共享同一语义路径。

## 4. 文档系统建议

采用“索引 + 专题子目录”：
1. `docs/index.md`：总入口（TOC）
2. `docs/design-docs/`：设计与原则
3. `docs/product-specs/`：产品合同与用户行为
4. `docs/exec-plans/`：执行计划与技术债追踪
5. `docs/references/`：外部参考与术语
6. `docs/generated/`：自动生成事实（schema、接口）

## 5. 变更流程（建议）

1. 先更新合同或架构文档（定义预期行为）。
2. 再更新实现与测试。
3. 最后回填执行计划与学习记录。

## 6. 审核清单

每次架构相关改动至少回答：
1. 边界是否更清晰？
2. 是否新增了不可见耦合？
3. 是否能用测试与 lint 机械验证？
4. 文档入口是否可被下一次 agent 运行快速发现？
